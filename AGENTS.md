# artel-collector

`@kk-forge/artel-collector`, the npm library a product uses to send its usage events to the intake service (idea-packer's `/v1/public/relay`). The intake's contract is its `GET /v1/public/schema`, and its code is `backend/relay` and `backend/product` in idea-packer. README.md is the library's own documentation.

## Commands and release

README.md → Development lists the commands, and README.md → Release how a version reaches npm.

## Rules this code relies on

- The core reaches the host only through its clock, the host's time zone through `new Date`, `crypto.getRandomValues`, `TextEncoder`, the WHATWG `URL` constructor to check `endpoint` and read a page and a referrer, and in `newHttpTransport` `fetch` and `AbortController`. The product passes the intake's address or its own `transport`, a `storage`, and optionally `lock` and `clock`. The platform constructors in `src/web.ts`, `src/extension.ts` and `src/desktop.ts` fill these in and call `newCollector`, and the core imports none of these modules. `uiLanguage` comes only from the product's option: no constructor guesses it. `newContentScriptCollector` in `src/extension.ts` builds no collector: its `track` is `forwardTrack`, and its other methods do nothing or report to `onError`. The options, the states and the `Collector` interface are in `src/collectorTypes.ts`.
- `mode` is a discriminated union in the options types: only `identified` takes `getId`, only `pseudonymous` and `identified` take `browser`, only a web or extension platform takes `browser`, and only platform web takes `getPage`. `StateOf<M>` keeps a channel's `setState` to the states up to its mode: `anonymous` < `pseudonymous` < `identified`. Keep such rules in the types. The runtime checks only what types cannot hold, such as a browser's major version, an untyped caller's state, the channel key, a storage value that is not a string, and an event the intake would drop. `checkedBuild` in `src/hostInput.ts` makes `newCollector` throw a `TypeError` that names the option. It throws for options that would make the intake refuse every envelope, so a bad build fails its first run. An unknown `mode` reads as anonymous, and a duration that is no finite number from 0 takes its default. A language that breaks the format often comes from the browser, so the collector leaves it out and reports it. The event checks live in `src/eventCheck.ts`: the name and param forms, the value types, 64 characters of a string, 16 params and the params of a system event. `track` and `acceptForwarded` share `eventProblem`. The intake alone applies its address rule to params. The version and language checks are in `src/fields.ts`, and the browser's in `src/browser.ts`. `src/pagePath.ts` reads a page and a referrer with the platform `URL`. It writes a page segment that holds `@` or a look-alike, IPv4 or IPv6 as `:address`, and a segment that starts a URL with the rest of the path as one `:address`. It drops a referrer whose host is an IP or holds an `@`. The intake masks the page and drops such a referrer by its own wider rules, so the two sides need not agree to the character. `src/page.ts` reads an event's page fields from any `getPage` when a method is called. At record time it sends the referrer only with a collector's first recorded `page_view`, and drops a `page_view` of the page the last recorded one sent. A report that quotes host input uses `quoted` from `src/hostInput.ts`, which never throws.
- The mode limits which states a channel takes, ranked in `channelTakes`. The stored state, `opted_out`, `anonymous`, `pseudonymous` or `identified`, decides what an envelope carries, and a stored state above the mode reads as `anonymous`. `fieldsForState` in `src/stateFields.ts` alone decides what a state sends: the languages, whether ages are exact, the kind of id an envelope carries with the browser, and whether events carry page fields, which only platform web sends. `pseudonymous` sends what `identified` sends, and only the id's source differs. `record`, `recordOptOut`, `uninstallParams` and `newEvent` use only its result, and no other code branches on the state for it. Only `identityIn` in `src/collector.ts` reads an id: the install id in the pseudonymous state, which `installState` makes as 32 hex characters and keeps in `install_id`, and `getId` in the identified state. An envelope with `id` carries `id_kind` too, and the intake keeps the id only when its kind is within the channel's mode. The intake applies the same rules to any envelope without an id, so a change to what a state sends goes to idea-packer's `backend/relay` too.
- An envelope of the identified state whose id is not known yet is queued with `awaitsId`, and `queue.seal` fills in the id, its kind and the browser just before its first request. The install id is always known, so a pseudonymous envelope never waits. `noteId` keeps the last id of either state in `last_id`. Another id drops the envelopes with an id or awaiting one and ends the session, so none is sealed under another user's id. `forget` of the last id drops them too and stores a last id no id equals, so the next id counts as another user.
- Leaving `pseudonymous` or `identified` for any other state calls `leaveIdentity`: it forgets the last id, drops the envelopes with an id or awaiting one, and deletes the install id. So a change between the two id states counts as another user. A forget, from `leaveIdentity` or the public `forget(id)`, drops the id's envelopes and stores a request `{ key, id }` in `forgets`. The outbox sends the stored forgets before the envelopes of each send, to the endpoint's `forget` address or through the product's own `transport`, which tells it by a body without `events`. A forget follows the retry rules of an envelope, and any other status outside 2xx, such as a test key's 403, drops it and reports it once. `setState` stores the state before it leaves, and the first call of a run leaves the last id that a state without an id still holds, so a stopped run still forgets.
- An event goes to the queue in storage at once and leaves it once the intake answers or a drop rule removes it. A send leases its envelopes and seals each one just before its first request, storing that request's body. Every attempt sends the stored body with its `batch`, the envelope's queue id, byte for byte, since the intake drops only an exact repeat. After 0, 429 or 5xx the outbox stores in `retry_at` the time before which no send of any context starts, its own doubling wait or the longer `Retry-After` of a 429 or 503, so every context and every `flush` keep it. It keeps a later stored time, and stores again as five minutes from now one more than five minutes ahead or one that is no time. Just before a request the outbox drops an envelope with an event dated before yesterday in UTC, which keeps every repeat inside the intake's 72-hour window for `batch`. Read `src/queue.ts` and `src/outbox.ts` before changing either.
- The collector takes the first-of-period, install and version marks when it queues an event, and counts the event's local day among the active days. A drop gives back the marks of an envelope no request carried yet, one no earlier seal stored a body for, through `install.giveBack`: an opt-out, leaving a state with an id, another id, the 20-envelope cap and a stale event. A failure after the marks were taken and before the queue holds the event gives back the marks that call took. An envelope a request carried keeps its marks on every drop, since the intake may have stored it. A forget gives back the marks of every envelope of the id, since the intake deletes those events. A day given back leaves the active days at any count. Giving back an `updated` clears the stored version only while it is still that envelope's version. The queue's removal methods return the envelopes whose marks may go back.
- An `opted_out` takes an envelope of its own, marked `isOptOut`, which nothing joins and which an opt-out and the 20-envelope cap keep. The queue keeps at most two of them. Both caps apply when the queue adds an envelope. `setState` stores `opted_out` before it drops the queue, and the first call in that state drops what a stopped run left.
- Any script of the origin can write the storage, and it can already call `track` and post to the intake. So the queue does not check what it finds stored: it reads a stored queue that is no JSON list as empty and reports it once, and skips an item without a `qid` and an `envelope` with a list of `events`. The intake applies every rule of its own to whatever arrives.
- `newCollector` wraps the storage with `newChannelStorage` from `src/storage.ts`, which keeps each name, such as `queue`, under `artel.<channel key>.`. So collectors of different keys over one storage share no stored value, and the modules name their keys without the prefix.
- Every collector method resolves and never rejects. A failure goes to `onError`.
- Tests drive the collector through `tests/harness.ts`: `FakeClock` owns time and timers, `FakeFetch` the network. No test fakes the global timers.
- The shape checks of a forwarded message and of the stored queue are written by hand, without a schema library. The checks are small, and the package keeps no runtime dependencies.
